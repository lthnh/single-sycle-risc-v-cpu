## Milestones

### 0. Freeze The Contract

- Specify supported instructions and legal `funct3`/`funct7` combinations in a table.
- Define safe behavior for unsupported/reserved encodings: no register write, memory write, or
  control transfer.
- Define byte-addressed PC/data addresses and word-indexed memory semantics.
- Define deterministic programming behavior, including top-level program address, write edge,
  PC hold, and suppression of architectural writes while programming.
- Keep ordinary RTL/testbenches on IEEE 1364-2005.
- Record the user decision that overflow will be repaired, tested, and integrated into the ALU,
  while remaining non-architectural unless explicitly exposed for debug.
- Select an executable synthesis reference and concrete/default FPGA part if Vivado is used.

Exit: every later test maps to a documented behavior and no placeholder synthesis command remains.

### 1. Portable, Red-Capable Build

Critical files: root and nested `Makefile`s, `inc/assert.vh`, `inc/common.vh`, existing TBs,
`.gitignore`, and a new shared make fragment/source manifest.

- Remove the bad top-level include.
- Replace `$HOME` discovery with a repository root derived correctly from the shared make fragment
  (`../..` from `tests/mk/common.mk`), with parse-time path validation.
- Use deterministic explicit source manifests rather than `src/**/*.v` shell globbing.
- Create output directories automatically; make clean idempotent; retain existing target names.
- Add strict `-g2005 -Wall` compile/elaboration targets; do not call this full lint unless backed
  by an actual lint tool.
- Remove shared RTL timescale leakage.
- Rewrite assertion macros with parenthesized operands, an error count, one terminal result
  sentinel, and no false-success `$finish` behavior.
- Migrate every discovered testbench, not a hard-coded count.
- Add a permanent negative harness test and include `mul_tb` in aggregate execution.

Exit: all existing tests run from a fresh clone, an intentional failing assertion makes Make fail,
and top-level elaboration runs even if later functional milestones are still red.

### 2. Deterministic Programming, Reset, And PC

Critical files: `src/single_cycle_cpu.v`, `src/program_counter.v`,
`src/instruction_memory.v`, `src/instruction_increment.v`, and their TBs.

- Add top-level reset and program-address inputs.
- Add explicit PC hold/enable behavior rather than overloading reset as an enable.
- Separate instruction fetch and programming addresses.
- Gate PC advancement, register writes, and data-memory writes while programming.
- Feed PC, not instruction bits, to PC+4 and branch-target logic.
- Convert byte PC addresses to word indices explicitly.
- Use nonblocking instruction-memory writes and remove independently overridable derived widths.
- Update all callers and direct tests atomically with interface changes.

Exit: arbitrary instruction words load deterministically; programming cannot mutate architectural
state; reset, hold, address conversion, and fetch visibility are directly tested.

### 3. Base Datapath Correctness

Critical files: `src/single_cycle_cpu.v`, memories, register file, increment/target modules,
`src/control_unit.v`, both decoders, and `src/arithmetic_logic_unit.v`.

- Correct data-memory byte-to-word addressing and define boundary behavior.
- Eliminate all decoder and ALU latches with default-first combinational assignments.
- Normalize `funct3` declarations to `[2:0]` and fix malformed literals.
- Add directed tests for safe decoder defaults, register-file x0 semantics, memories, increment,
  target calculation, and mux/control behavior.
- Add a minimal CPU signature program using only behavior repaired by this milestone: `addi`,
  `add`, `sub`, `and`, `or`, `sw`, `lw`, `beq` taken/not-taken, and `jal`. Do not include `slt` yet.
- Prefer a designated memory signature over broad hierarchical register inspection; centralize any
  unavoidable hierarchy access in one testbench task and add a watchdog.

Exit: the minimal CPU program produces its expected signature, unsupported opcodes cannot mutate
architectural state, synthesis reports no latches, and leaf suites remain green.

### 4. ALU Architecture And Overflow

Critical files: `inc/alu.vh`, `src/arithmetic_logic_unit.v`, `src/alu_mods/{add,sub,overflow}.v`,
adder tests, subtraction test, and new ALU/overflow tests.

- Establish one guarded source of truth for ALU operation encodings.
- Replace global macro-selected RCA/CLA implementation with a Verilog-2005 module parameter and
  named generate branches; parameterize `sub` correspondingly.
- Add required `generate/endgenerate` constructs and remove hard-coded component-width arithmetic.
- Instantiate `add` and `sub` in the ALU.
- Repair signed `slt`, zero-extension, and combinational `zero_out`.
- Rename subtraction's raw carry output accurately.
- Recut overflow around decoded add/sub intent and operand/result signs; integrate and test
  `overflow_out` in the ALU without treating it as an RV32I trap.
- Cover signed boundaries, carry/borrow semantics, overflow boundaries, zero flags, and RCA/CLA
  functional equivalence.

Exit: either adder implementation is selected independently of compilation order; ALU and
overflow outputs are fully combinational and tested; the CPU signature extends through `slt`.

### 5. OP, OP-IMM, And Conditional Branches

Critical files: `inc/alu.vh`, ALU, control unit, both decoders, top-level CPU, and CPU/decoder TBs.

- Widen ALU control and add `SLL`, `SLTU`, `XOR`, `SRL`, and `SRA`.
- Decode OP and OP-IMM legal combinations explicitly, including SUB/SRA distinctions.
- Implement all six conditional branch predicates and reject reserved branch encodings safely.
- Add exhaustive decoder tables and directed ALU boundary vectors.
- Extend the CPU signature program with every supported R-type/immediate counterpart, all six
  branches taken and not taken, signed/unsigned extremes, and shifts by 0, 1, and 31.

Exit: the supported-instruction table and tests agree; reserved encodings have no architectural
effect; the full CPU signature test and watchdog pass.

### 6. Standalone Multiplier

Critical files: `src/alu_mods/mul.v`, multiplier shift/register modules, and multiplier TBs.

- Define a clear start/busy/result protocol.
- Give each state register one sequential owner, reset all state, capture both operands, and fix
  cycle count and partial-product alignment.
- Test zero, one, maximum values, powers of two, back-to-back operations, and timeout behavior.
- Keep multiplication outside the CPU datapath per scope.

Exit: deterministic synthesizable multiplication works repeatedly without reset between jobs.

### 7. CLA Structural Repair

Critical files: modified full adder, four-bit CLA/lookahead modules, and direct CLA TBs.

- Correct propagate generation and update the direct reference model.
- Preserve exhaustive numerical tests and add checks for documented generate/propagate semantics.
- Record structural/synthesis evidence of intended carry architecture without imposing a brittle
  timing threshold.

Exit: arithmetic remains correct and propagate/generate outputs match their definitions.

### 8. Consolidation And Platform Portability

Critical files: `.github/workflows/*`, `tools/tcl/*`, `tools/slang/*`, `README.md`, `AGENTS.md`,
`opencode.jsonc`, style documentation, `.gitignore`, and shared manifests.

- Add CI for strict compilation, all tests, negative-harness validation, and synthesis.
- Add Windows/Vivado Tcl only after the Linux reference flow is stable, consuming the same source
  and test inventory.
- Complete Slang configuration from the same manifest.
- Replace normative SystemVerilog guidance with concise project-specific Verilog-2005 rules;
  retain lowRISC guidance only as clearly non-normative reference material.
- Correct README/AGENTS commands, scope, structure, prerequisites, and generated-file ignores.
- Do not promise UVM support when no UVM tests exist.

Exit: Linux and Windows flows cover the same inventory, documentation commands are executable,
CI is green, and a fresh-clone acceptance run needs no manual setup.
